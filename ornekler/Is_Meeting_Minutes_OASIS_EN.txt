List Bullet | James described MODEX as a catastrophe-model execution and reporting environment, not a general hazard visualization or standalone vulnerability-analysis application. It currently focuses on probabilistic catastrophe-model workflows.
Heading 2 | 2.2 OED input files and validation
List Bullet | Exposure inputs use the OASIS Open Exposure Data (OED) conventions. James explained that historical hosted models can use different OED versions; new integrations should ideally concentrate on newer versions to avoid supporting many legacy schemas.
List Bullet | In answer to T-Rupt’s version question, the latest OED version was identified in the meeting as version 5; the current OASIS Results Data (ORD) format was identified as version 1.
List Bullet | The standard exposure package includes an account file, a location file, and two reinsurance files. The minimum for a portfolio is the account and location files; the reinsurance files become relevant for net-loss calculations.
List Bullet | Users can upload files via drag-and-drop, file selection, or programmatic API workflow. CSV and Parquet formats are supported.
List Bullet | Initial file validation checks format and completeness (e.g., numeric fields populated with text or required columns missing). A valid file receives a green check; otherwise, the user receives an actionable error report.
List Bullet | Input files cannot be corrected interactively within MODEX: users correct files externally and upload revised copies. James emphasized immutability and auditability—uploaded data are not silently edited inside the platform.
List Bullet | Uploaded files are initially independent. Portfolio Manager creates an explicit association between the selected account, location, and optional reinsurance files, after which a second validation assesses cross-file consistency.
Heading 2 | 2.3 Portfolio Manager configuration
List Bullet | Each portfolio is named and categorized as property catastrophe or cyber. Users select previously uploaded input files and save the portfolio.
List Bullet | The default assumption is a single currency for all exposures. For multi-currency datasets, users must manually specify exchange rates in a currency-conversion table; rates are not dynamically obtained from OASIS.
List Bullet | Optional free-form tags help brokers identify and search prior work, such as portfolios from different cedants. Tags are an organizational aid, not a required model input.
List Bullet | Portfolio validation confirms integrity between the linked account/location/reinsurance files before the portfolio can be used for modeling.
Heading 2 | 2.4 Analysis Manager and configuration controls
List Bullet | Users create an analysis by choosing property/cyber, a validated portfolio, and a licensed model. An OASIS example model was selected in the demonstration.
List Bullet | Event-set choices may include a probabilistic catalog or historical event catalog, depending on the model; users can select events when that option is available. A separate model configuration / occurrence set may allow alternatives such as long-term assumptions versus future climate scenarios.
List Bullet | A pre-execution acceptance/coverage check can generate and inspect model input files without running a full loss calculation, helping determine what proportion of a portfolio can actually be modeled.
List Bullet | An optional loss threshold discards very small simulated losses from the calculation. James noted that he knew of few users applying that option.
List Bullet | Monte Carlo sample count is configurable in the OASIS financial workflow. James explained the computational trade-off: higher samples increase workload; portfolio size and spatial diversification may influence the sensible choice.
List Bullet | Users can attach a custom return-period table to override a model’s default schedule, including nonstandard metrics requested by certain markets (e.g., 1-in-30-year).
List Bullet | ORD results can be exported as CSV or Parquet. Analysis presets can prepopulate recurring run settings; reporting presets can similarly retain output-selection preferences, although some manual adjustments may be needed.
Heading 2 | 2.5 Outputs, reporting, and platform limitations
List Bullet | Reportable metrics include exceedance-probability (EP) curves, average annual loss (AAL), year loss tables, and other supported loss outputs. Views can be produced for full portfolio or grouped by account, location, country, construction code, state, and other attributes available in the OASIS financial model.
List Bullet | Multiple output views and perspectives can be requested, including ground-up, gross, and net/reinsurance losses when the model and input data support them.
List Bullet | Run status and progress are visible on the dashboard. Completed analyses provide high-level inputs and execution information, including total insured value (TIV), number of locations, and run time.
List Bullet | Individual output files can be downloaded, or all requested output artifacts can be downloaded together.
List Bullet | MODEX does not currently provide downstream analytics for merging loss outputs from different models. James indicated that cross-vendor aggregation capabilities are expected in ORD version 2 and reported an anticipated end-of-2026 release, but this was a forward-looking estimate, not an available feature.
